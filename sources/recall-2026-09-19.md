`article`, `region` 인덱스 예시가 주어지고 enrich 후의 결과 인덱스도 제공.
기사 예시에는 `@timestamp: 2015-12-31T00:00:00Z`, `vector: {cosine ~~}`, `region: us-northest`, `title: adsasdas`, `article_id: art-100`, `body: asdasdsad`가 제시됨.

`regions` 인덱스 예시:

```json
{
  "region_id": "us-northest",
  "region_name": "US",
  "description": "adasdsadsa"
}
```

`region`의 `region_id`와 `article`의 `region` 필드를 매칭하여 아래와 같은 `region_info` 객체가 추가.

```json
{
  "region_info": {
    "region_id": "us-northest",
    "region_name": "US",
    "description": "adasdsad"
  }
}
```

## 9. ingest pipeline

주어진 인덱스가 존재하며, 해당 인덱스에는 매핑 및 문서가 존재하지 않으며 이는 올바른 상황이라고 설명이 주어집니다.

task9 이라는 ingest pipeline을 생성하고, 주어진 인덱스를 재생성하지 않으면서 default pipeline으로 설정.

- grok 프로세서를 이용하여 message필드에서 response_status, duration_ms 필드를 생성
  - message 필드 패턴은 주어집니다. `HTTP %{NUMBER:response_stauts} ABC %{??:duration_ms}`
- convert로 duration_ms를 integer로 변환
- raw_time 필드를 date 타입으로 바꾸고, 이름도 @timestamp로 변경

매핑 및 문서가 존재하지 않아 파이프라인 생성 후 _simulate 시 동작하지 않아 직접 문서를 작성하여 검증해야 합니다.
